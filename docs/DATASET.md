# CSV outputs and field meanings

Main produces measurements and evidence CSVs. The former merged EDA tables, plots, bootstrap summaries, and SQL imports are not generated by this branch. Existing export packages are historical artifacts and remain unchanged.

## Producing and opening these files

Follow [RUNNING.md](RUNNING.md) for environment setup and collection commands. `run_experiment`, `run_controlled`, and `run_live` export CSVs automatically; `run_scenario` does not. A suite adds its combined CSV and comparison manifest, and a campaign keeps the separate suite/run directories rather than creating one global EDA table.

Start with a successfully completed run's `run_status.json`, then inspect `csv/dataset_report.json` and `csv/quality_report.json` before opening its tables in your preferred CSV/EDA tool. Keep the source snapshot, status, and suite/campaign manifests alongside the CSVs. To regenerate derived CSVs from existing complete lab traces, see the `export_dataset` example in the usage guide; use the original duration and do not export while collection is running.

## Current files

| File | Row unit | Meaning |
|---|---|---|
| `csv/ue_application_100ms.csv` | run × UE × 100 ms | Application RX bytes, goodput, mobility, warmup, and scenario context. Use it for traffic totals. |
| `csv/ran_features_100ms.csv` | run × UE × measured cell × 100 ms | Radio features plus repeated application context. Do not sum repeated UE application values here. |
| `csv/bearer_intervals.csv` | original bearer measurement interval | PDCP/RLC intervals retain their original timing rather than being repeated into 100 ms rows. |
| `csv/ai_shadow_scores.csv` | UE × cell × decision | Observed SINR and next-window forecast. |
| `csv/ai_shadow_decisions.csv` | UE × decision | Policy recommendation, reason, predicted gain, and optional robust budget. |
| `csv/ai_shadow_reference_decisions.csv` | UE × decision | Clean-input reference on the same attacked network trajectory. |
| `csv/ai_shadow_attack_audit.csv` | UE × cell × decision | Clean/observed inputs, biases, forecasts, attack support, and target identities. |
| `csv/adversarial_dataset.csv` | run × UE × cell × window | Radio data joined with attack-audit fields by `check_evasion`. |
| `csv/ai_control_decisions.csv` | decision | Recommendations joined to later control evidence by `check_control`. |
| Suite `dataset.csv` | condition × radio row | Concatenated per-condition adversarial data with `experiment_condition`. |

`comparison.json` contains suite-level received-byte differences and control/attack counts. It is not a statistical significance report. `quality_report.json`, `dataset_report.json`, run statuses, and manifests preserve validation and source/model provenance. Optional flow-monitor and UDP-event exports are produced only when their raw inputs exist.

## Application and radio fields

- `run_id`, `ue_imsi`, and `nr_cell_id` identify the run, simulated UE, and measured cell.
- `window_start_s` and `window_end_s` are simulator-time boundaries, not wall-clock capture timestamps.
- `rx_bytes` and `app_goodput_mbps` measure application data received during a window. Goodput is bytes × 8 / seconds / 1e6.
- `is_warmup` or `ue_is_warmup` flags warmup; rows remain in CSV but summary comparisons exclude them.
- `traffic_profile`, `direction`, `x_m`, `y_m`, and `speed_mps` record traffic/mobility context. Radio rows use `ue_` prefixes for copied application values.
- `sinr_*_db` summarizes mean, last, standard deviation, minimum, and maximum SINR; `sinr_sample_count` records coverage.
- `cell_dl_*` contains cell-level transport-block/PHY summaries, not per-UE application throughput.
- `last_recorded_path_cell_id` summarizes a recorded path event and is not a complete serving-cell state feed.
- `ue_nr_rrc_cell_id`, `ue_nr_rrc_state`, and `ue_control_required` record actual control state when that interface exists.
- `attack_present` and `attack_type` describe scheduled UDP load, not model-input evasion.

Missing numeric observations stay empty. The model uses training medians for missing features; export does not fabricate zero radio measurements. Existing but header-only bearer traces produce an empty canonical table and explicit availability/count metadata. A missing required raw file is still an error.

## Model-input audit

The predictor uses eight features: SINR mean, last, standard deviation, mean change, last-minus-mean, cell DL block count, corrupt-block fraction, and its missingness indicator. `aml_clean_` and `aml_model_` fields preserve clean/observed feature versions.

`aml_delta_sinr_db` and `aml_previous_delta_db` describe current/previous bias. A constant window bias changes mean and last values but not standard deviation or last-minus-mean; the temporal difference also depends on previous bias.

`aml_event_active` describes the event support; `aml_input_perturbed` includes historical bias effects. `aml_audit_available=0` means missing audit, not a verified clean sample. In a present audit, zero event/input flags explicitly indicate inactivity. An empty active-event list means no applied active evasion event. Never infer activity from the condition name alone.

Clean and observed forecasts in an attacked row use the same network state. They are not the separate matched `none` run. Compare whole-run traffic against that suite's clean run when assessing simulated network effects.

## Decision timing

A decision is timestamped at the end of a completed window. Its new action cannot cause bytes already received during that same window. Join a decision to subsequent application windows only after accounting for request and confirmation time. A later target-connected event confirms state at that instant, not occupancy throughout the whole window.

Current collection does not automatically create `prior_decision_*` application columns or same-window AML application joins. Those columns exist in the historical normalized export package; do not assume they are present in newly collected application CSVs. Build and validate such joins explicitly in later EDA.

## Sources, splits, and later EDA

Each new suite/campaign snapshots `scenario.cc` and records `scenario_sha256`. Run statuses preserve the selected source and executable identity. Model provenance records the training/validation sources. Keep different scenario, backend, predictor, access, defense, duration, and epsilon settings identifiable.

Use separate recorded seeds, runs, paths, and CSV hashes for training, validation, and test. Alpha is chosen on validation data, not test data. Default same-run UE splitting is a pilot. Keep adjacent windows, cell rows, and matched conditions of a seed together when assigning folds; repeated clean runs at different budgets are not independent trials.

The old `application_dataset.csv`, `radio_dataset.csv`, `run_summary.csv`, and `target_gap.csv` package remains under `exports/` with its original provenance. It was produced by the removed analysis stage. Main now leaves EDA, aggregation, plotting, and statistical intervals to the user, using the per-run CSV and suite comparison outputs above.
